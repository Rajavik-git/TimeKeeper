# Implemented interface

The approved six-screen visual design uses a floating 14 px-radius navigation card, local Geist fonts, the monochrome **The Seal** mark, light and dark graphite palettes, and responsive tables. It contains six screen tabs, a compact session chip, and icon-only Light/Dark/Auto controls. Below 1100 px, tabs show icons only; the phone layout can scroll as a single column. The desktop shell fits a 1440×900 or 1280×800 viewport without page scrolling. Long tables, client grids, settings content, billing content, and Source columns scroll internally. The reading scale is 15 px body, 13.5 px secondary, 12.5 px minimum, 24 px page headings, 16.5 px card headings, 24 px indicator values, and 50 px table rows. Keys 1–4 open My day, Cases, Pre-invoices and Source outside form fields.

The shared formatter in `src/frontend/shared/format.ts` supplies English money, rate, percentage, date and duration strings. Money uses two decimal places and comma grouping; rates use whole euros per hour; durations use hours and minutes. This changes display only. The calculation layer still sums precise effective milliseconds before rounding a combined total up to whole minutes.

- **My day** begins with a one-click validation card for recognized periods alongside the period-bound unanswered case question. Four simple indicators show time, fees, unrecorded coverage, and pending validation. The seven-column table combines time and source review in Status, keeps Validate and Sources visible, and moves correction and billing actions into a More menu. Corrected duration shows the detected value below. An optional marker suggestion remains available; Answer targets the question's assignment revision. Adding a hearing or meeting creates a source-free manual period with explicit duration.
- **Cases** opens on a practice dashboard with four indicators, a scrollable client grid, client billing bars and attention items. Selecting a client opens its facts, indicators and case cards; selecting a case opens its facts, budget gauge and Time/Markers tabs. A clickable breadcrumb returns to the client or dashboard. Time, fees, pending validation and budget use are calculated from canonical periods and billing snapshots in `src/frontend/calculations/cases.ts`. The catalogue and marker editor use the retained demo routes; edits synchronize catalogue fields to canonical tables used by invoice validation.
- **Pre-invoices** calculates a draft in React from effective period durations. The draft groups minutes per case, applies the case > client > base rate, and shows expenses, disbursements, VAT and completeness. Issuing sends frozen lines and totals; the API checks ownership, validation, revisions and billing state. Existing issued invoices cannot be ordinarily unbilled through the period control.
- **Source** lists each linked observation's availability and independent validation state. The historical demo includes a simulated cursor, recognition evidence, Jev reviews, audit and source-pack controls. Newly created canonical periods open their own source list by opaque ID.
- **Settings** edits client, case, rate, task and rule configuration. Unresolved base-rate estimates use canonical precise durations.
- **Desk and floating pill** display active session, current case and current-period duration. The simulated desk fills the available height and both pills display the small Seal mark. They no longer advance a fictional fee timer. Screenpipe owns recording and session commands; pause and close controls await integration.

`tests/acceptance/smoke.py` checks all six screens at 1440×900 and 1280×800, including document height, minimum visible text size and no horizontal My day table overflow. It also exercises the one-click recognized-period validation, the Cases hierarchy, phone layout and pill. Set `CAPTURE_DIR` to retain light and dark 1440×900 screenshots for each screen and both deeper Cases levels. These are browser checks, not native desktop or provider acceptance.

The navigation chip shows the active session start time and explains on hover that closing the interface leaves it active. Identifiers and revisions are hidden in the main navigation and My day. These are local database states, not a claim that Screenpipe recording is connected. The [mockup gap](../MOCKUP_GAP.md) records missing native/provider acceptance.
