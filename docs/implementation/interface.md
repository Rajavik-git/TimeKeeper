# Implemented interface

The approved six-screen visual design uses a 232 px sidebar, a 48 px top bar, local Geist fonts, the monochrome **The Seal** mark, light and dark graphite palettes, and responsive tables. The brand in the sidebar is a static label; the single-user footer has been removed. The desktop shell fits a 1440×900 or 1280×800 viewport without page scrolling. Long tables and client grids scroll inside their cards; the phone layout can scroll as a single column. Keys 1–4 open My day, Cases, Pre-invoices and Source outside form fields. Search, Help and capture pause are visible but unavailable because provider integration is not implemented.

The shared formatter in `src/frontend/shared/format.ts` supplies English money, rate, percentage, date and duration strings. Money uses two decimal places and comma grouping; rates use whole euros per hour; durations use hours and minutes. This changes display only. The calculation layer still sums precise effective milliseconds before rounding a combined total up to whole minutes.

- **My day** displays combined precise work rounded once, React-calculated fees, an explicit coverage gap and periods needing time validation. Each row separates detected and corrected duration, time validation, per-source validation and availability, and billing status. An unresolved period shows a period-bound question and an optional marker suggestion; Answer targets the question's assignment revision. Manual off-screen time creates a source-free period with explicit duration.
- **Cases** opens on a practice dashboard with four indicators, a scrollable client grid, client billing bars and attention items. Selecting a client opens its facts, indicators and case cards; selecting a case opens its facts, budget gauge and Time/Markers tabs. A clickable breadcrumb returns to the client or dashboard. Time, fees, pending validation and budget use are calculated from canonical periods and billing snapshots in `src/frontend/calculations/cases.ts`. The catalogue and marker editor use the retained demo routes; edits synchronize catalogue fields to canonical tables used by invoice validation.
- **Pre-invoices** calculates a draft in React from effective period durations. The draft groups minutes per case, applies the case > client > base rate, and shows expenses, disbursements, VAT and completeness. Issuing sends frozen lines and totals; the API checks ownership, validation, revisions and billing state. Existing issued invoices cannot be ordinarily unbilled through the period control.
- **Source** lists each linked observation's availability and independent validation state. The historical demo includes a simulated cursor, recognition evidence, Jev reviews, audit and source-pack controls. Newly created canonical periods open their own source list by opaque ID.
- **Settings** edits client, case, rate, task and rule configuration. Unresolved base-rate estimates use canonical precise durations.
- **Desk and floating pill** display active session, current case and current-period duration. The simulated desk fills the available height and both pills display the small Seal mark. They no longer advance a fictional fee timer. Screenpipe owns recording and session commands; pause and close controls await integration.

`tests/acceptance/smoke.py` checks all six screens at 1440×900 and 1280×800, including the document height invariant, plus the Cases hierarchy, phone layout and pill. Set `CAPTURE_DIR` to retain light and dark 1440×900 screenshots for each screen and both deeper Cases levels. These are browser checks, not native desktop or provider acceptance.

The sidebar names an active session and explains that closing the interface leaves it active. These are local database states, not a claim that Screenpipe recording is connected. The [mockup gap](../MOCKUP_GAP.md) records missing native/provider acceptance.
