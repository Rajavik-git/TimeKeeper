# Implemented interface

The desktop interface has five top tabs: **My day, Cases, Billing, Activity, Settings**. The Desk pill settings and preview live under Settings; `?view=desk` also opens the preview directly. A floating navigation card holds the tabs, session chip, and Light/Dark/Auto controls. Below 1100 px, tabs show icons only. The Seal mark and local Geist fonts are shared by the web interface and pill. Page titles use 30 px and card titles use 19 px. Summary indicators are individual graphite tiles with a 16 px gap; they reflow to two columns at narrow widths. Desktop windows fit the 1400×950 layout at a scale between 0.62 and 1. Larger windows never enlarge it; widths below 900 px keep the responsive layout. Billing uses five case columns at desktop widths. Each desktop screen fits 1440×900 and 1280×800 without page scrolling; long content scrolls within cards.

The shared formatter in `src/frontend/shared/format.ts` uses US dollars, comma grouping, and two decimal places. New workspaces start with a blank identity, USD currency, a zero base rate, and a 0% tax rate. The tax line is hidden when its rate is zero. Existing local databases keep their records. There is no sample-data reset control or endpoint. The calculation layer sums precise effective milliseconds and rounds only a combined total up to whole minutes.

The shell and My day now follow the approved HTML mockup at 1440×900 and 1280×800 in light and dark themes. Shared selects draw the same small chevron and use Geist instead of the operating system's native arrow and font; tables sit directly on their parent cards without a second border or background. My day's prompt cards use a 20 px gutter, and its period table keeps client and case metadata on one line with ellipsis where needed. The page has Filter and CSV Export controls. The former toggles the pending view; the latter downloads the selected day's included periods. The global demo disclaimer and reset footer were removed from the shell.

The second visual pass aligned the day picker controls and calendar with the reference, right aligned each row's actions, and made an overridden duration bold above its original value. The standalone Desk pill's case selector also uses a local Geist font and custom chevron.

The polish pass adds 140 ms ease-out hover, pressed, focus, and entry states with reduced-motion support. A shared bottom toast reports explicit action results and errors; My day reports validation and CSV export, with Undo for leaving a period out. Bulk validation moves keyboard focus to the unresolved case card. My day's table has a bottom fade only while more rows are hidden, and duration editing reveals a pencil on hover without shifting the row. Empty tables with recorded periods offer an action, long client names expose their full value in a tooltip, and zero summary values show a muted dash.

The accessibility and product pass makes the shared focus outline opaque, raises muted text and dark border contrast, and uses Oxford for primary actions. Status messages appear at the bottom right for six seconds. Leaving Sources returns focus to the source button. The table's Filter popover selects a client and case, and Export downloads the visible periods with date, duration, and status. The question card disappears once every period has a case; after the final validation, the full-width card shows the period count, time, fees, and a Billing link. Coverage gaps show that manual entry is unavailable. The current API cannot undo an answered unknown-case question, so the assignment success message does not offer Undo; the reversible Left out action does.

The review pass limits My day table framing and pressed states to that screen. Sorting periods by case, work, or duration omits the independent coverage gap row; sorting by period inserts it chronologically. CSV follows the displayed sort, includes a UTF-8 BOM for spreadsheet compatibility, and prefixes formula-like cells with an apostrophe. Empty days show No work recorded without an in-card action.

The current local date updates at midnight and on focus or resume. Calendar limits and newly created expenses use that date. Mounted resources poll while visible, including filtered day, calendar, and Activity queries. Refreshing server data preserves the user's local Cases navigation. Billing includes cases with only outstanding expenses or disbursements. Clearing an optional case/client rate restores inheritance; an explicit zero remains a configured rate. Optional budgets can also be cleared. Batch validation refreshes already committed successes if a later request fails. Settings forms close when sections change; drafts and validation errors do not leak into another form. Search distinguishes a failed request from an empty result and ignores superseded responses. Invoice draft rows use cumulative allocation of the combined fee, so displayed and CSV amounts remain nonnegative and sum to that fee.

- **My day** has a keyboard-accessible calendar, server-filtered daily data, four summary tiles, one-click validation of recognized periods, and the unresolved case question. The calendar marks validated work with a green dot, days needing validation with a larger pending dot, and past empty days with grey hatching; the date button counts other days needing validation. Future days are disabled. The table has Period, Client · case, Work performed, Duration, and Actions. Assigned pending periods have an Oxford Validate button; validated periods have a green label. Sources stays available. Manual entry controls are disabled until session and time boundaries are defined. Coverage gaps remain separate from billable time.
- **Cases** has a dashboard, client level, and case detail. The dashboard shows Needs attention, To bill, total Cases, and monthly time; client cards, unbilled bars, and attention items follow. The Clients card sorts by unbilled amount (default), name, latest activity, case count, or rate; its choice lasts for the browser session. Each client row in To bill by client expands its case rows with title, reference, thinner bar on the client scale, amount or Flat fee, and unbilled hours. The chevron toggles the rows; the client and case rows navigate to their respective pages. Search uses a server route for accent-insensitive matches and shows recent, attention, and high-unbilled suggestions. Case detail has Time, Markers, source-pack export, and export history. Dashboard percentages compare with the same day of the previous month; their single explanation is in the page subtitle. An increase in To bill is a bad change.
- **Billing** starts with three summary tiles: Ready to invoice, Waiting for validation, and To bill in total. Their percentages reconstruct the prior position from stored cases, periods, validation dates, and invoice dates using current period state and rates. They are estimates, not frozen historical snapshots. A rise in waiting or unbilled money is red. Both Billing and Cases show No previous-period data when the prior value is zero, because a percentage cannot be calculated from zero. The overview cards show the latest TimeKeeper invoice when one exists. Incomplete coverage shows Resolve coverage gaps instead of Ready to invoice. Selecting a case shows its draft invoice lines, expenses, applicable sales tax, validation work, and Create invoice action. Issuing stores a frozen snapshot; the API checks ownership, validation, revisions, and billing state.
- **Activity** shows a case-labelled timeline with validation colours. Client and case filters query the API; manual and observed periods appear. The selected period, its sources, and audit trail occupy internally scrolling cards. Technical capture IDs and confidence values are hidden. A source pack can be exported for the selected period. Source packs are downloaded as JSON and a SHA-256 receipt is retained in the case history.
- **Settings** edits rates, tasks, rules, and Desk pill options. The pill can stay on top, show fees, time, or case, alert for unresolved periods, and withhold notices during calls. The preview shows an empty document placeholder. Native settings depend on the Tauri shell; the browser preview is simulated.

Table headers use `--subtle` backgrounds and `--ink-2` text, sort the underlying data, and expose `aria-sort`; numeric columns sort by value and place missing values last. My day's Actions header is right aligned. Scroll areas use 6 px scrollbars without arrows, with a transparent track and a thumb that appears on hover; Firefox uses its thin scrollbar mode. The final Oxford/Ink palette lives in semantic CSS tokens in `theme.css`: `--act`/`--act-ink` for text-only Validate buttons, `--ok`/`--ok-dot` and `--warn`/`--warn-dot` for statuses, `--bad` for unbilled bars, and `--sum-up`/`--sum-down` for summary percentages. Visible client names wrap rather than truncate.

The [MCP browser acceptance workflow](../../tests/acceptance/README.md) runs `tests/acceptance/smoke.mcp.js` through the connected Playwright MCP server. It checks five tabs at 1440×900 and 1280×800 in both themes, page and shell overflow, the My day columns and controls, Cases search, Billing detail, Activity, Settings, and the Desk preview. The workflow documents isolated demo data and optional screenshots. These are browser checks, not native desktop or Screenpipe acceptance. The [mockup gap](../MOCKUP_GAP.md) records remaining provider and native verification.

Manual entry controls are disabled until session and time boundaries are defined. The disabled control retains its explanation in a tooltip and accessible description without adding a separate visible notice row. The interface no longer fabricates a start time or a sample hearing label. My day uses the current local date, including its monthly summary title.

Calendar labels and date filters use the desktop's timezone. Previous-month comparisons clamp to the last valid calendar day. Activity's axis measures elapsed hours since each row's local midnight; clock labels retain the actual local times across daylight saving changes and overnight periods. Open periods remain open and do not acquire an inferred duration from the chart. Cases with no recorded opening date display Unknown.

Source packs contain canonical JSON metadata and stored observation text. Other client names are redacted from descriptive text. The optional application filter uses known saved app metadata; audio includes stored audio text. No media blur or audio fetch is implied. The current screens use the canonical catalogue and activity APIs described in the [implemented architecture](architecture.md).
