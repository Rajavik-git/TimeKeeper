# Windows desktop app

TimeKeeper's Tauri 2 shell loads `pill.html` in a floating window and `index.html` in a hidden main window. The Windows NSIS installer includes the built frontend and a Node API sidecar. The sidecar is a [Node 22 single executable application](https://nodejs.org/download/release/v22.13.0/docs/api/single-executable-applications.html) with the server, dependencies, schema, and fictional demo seed bundled into one file. If the SEA cannot pass its build-time startup check, the build uses the bundled Node executable with the standalone CommonJS API resource. Tauri locates the sidecar using [`bundle.externalBin`](https://v2.tauri.app/develop/sidecar/) and starts it through `tauri-plugin-shell`.

## Install and run

- Windows 10 (version 1803 or later) or Windows 11 with WebView2.
- No separate Node.js, npm, terminal, or API process is needed after installation.
- For building on Windows: Node.js 22.13 or newer, Rust with the MSVC toolchain, and Microsoft C++ Build Tools.

Build on Windows with `npm ci` and `npm run desktop:build`, or run the **Windows desktop installer** workflow manually. Download its NSIS `.exe` artifact and install it. The installer is unsigned and may trigger a Windows SmartScreen warning. On launch, the shell starts the API at `127.0.0.1:8787`, positions and shows the always-on-top pill at the top center of the primary monitor, and keeps the main window hidden. The tray offers **Open TimeKeeper**, **Show/Hide pill**, and **Quit**. Closing the main window hides it; Quit terminates the API sidecar.

On first launch the sidecar creates `timekeeper.db` in Tauri's application data directory, installs the existing demo schema and seed, and imports the canonical demo periods. Later launches reuse the database and preserve local changes. The API binds only to loopback. The desktop WebView can access it from the configured Tauri origins.

For development, run `npm run dev:server` in one terminal and `npm run desktop:dev` in another. The development build uses the separately started API. `npm run api:bundle` builds the standalone API script; `npm run api:sidecar` also builds and smoke-checks the current platform's SEA or fallback executable. The Windows workflow runs tests and typecheck before packaging and uploads the NSIS installer artifact.

The pill polls the local API every five seconds for the active session, current work period, catalogue, and pending questions. Its default Billing style shows the current case, calculated period amount, and count of periods needing time validation. The panel shows period duration, amount, today's calculated fees, pending periods with individual and batch validation, guarded case answers, and case selection. The Pause/Resume button persists a pause bound to the active session in the local demo database and enables or disables the Windows foreground-window watcher through Tauri; it does not control Screenpipe recording.

The pill listens for the Tauri `active-window-changed` event with `windowTitle` and `appName`. After a three-second debounce it calls `POST /api/recognize` and offers the suggested open case, alternatives, and all open cases. Reference matches with sufficient score can auto-confirm after a visible 20-second countdown; lower-confidence suggestions wait for an explicit decision. A choice uses `POST /api/pill/decision`, which applies the existing guarded switch, assignment, exclusion, or validation service and returns a five-second Undo token. `POST /api/pill/undo` reverses that choice only while the affected periods remain unchanged; undoing a case assignment changes the effective case again, so time validation is required again. A switch ends the current open period and creates a new canonical period with the selected case or an unresolved assignment; **Not client work** creates an excluded period in the same transition transaction. The switch stores the window title and app name; My day and Activity read the resulting canonical period. Selecting a case in Other case or Which case applies it immediately, closes the prompt, and briefly confirms the result inline in the pill; Confirm, Not client work, and Validate also close their popups. A high-confidence prompt slides away when its countdown completes. The browser pill and Settings preview offer **Simulate file switch** with fictional demo document names so the flow can be tried without a Windows window event. A title without a file extension and without a case suggestion stays silent, including Windows Program Manager. Every notification has X and Later controls; Escape or clicking the pill also dismisses it without changing a period. A pending question remains available in the panel and in My day after dismissal. A prompt without a suggestion keeps Confirm disabled and readable until a case is chosen through Other case.

The demo does not derive continuous work duration from a file observation. A newly opened period stays incomplete until a duration is supplied through the established workflow. Its live pill timer is a display estimate while open, subtracts locally persisted pill pauses, and is not written as detected duration. The collapsed pill has a 24 px Pause/Resume button that uses the same persisted pause as the panel and disables or enables the Windows foreground watcher. The button's recording label refers to this pill control; it does not pause Screenpipe capture. Validation buttons are available only when the period has a case and an effective duration. Recognition uses the existing weighted case markers against open cases and never silently assigns a low-confidence suggestion.


On Windows, the desktop shell checks the foreground window every 1.5 seconds and emits `active-window-changed` to the pill when its title or executable name changes. System shell windows, TimeKeeper windows, and unrelated apps are ignored; document and work apps or titles with a supported document extension pass the filter. The `set_watch_enabled` Tauri command pauses or resumes this watcher; it does not pause Screenpipe recording. The watcher is not built on other platforms. The pill's event handling and case-change notification are implemented separately.

The Windows pill disables the native window shadow, border, and rounded corners. React measures the visible pill, panel, or notice and sends its exact width and height to Tauri, which centers the resized window on the primary monitor. The page root has a transparent background and no outside shadow or blur; only the rounded surfaces paint. Light and dark surfaces use a translucent tint, a 20 px backdrop blur with 160% saturation, and inset hairlines. Desktop content behind the WebView may remain unblurred where WebView transparency does not support backdrop sampling, while the tint remains visible. The browser Desk preview loads the same pill page and styles.

Linux verification covers the bundled API and a local SEA serving `/api/state` from a newly seeded temporary database. The Windows workflow checks the Windows sidecar before packaging. Native installer launch, tray behavior, WebView loading, and macOS behavior still require platform acceptance. The current icons are placeholders.
